# Belajar Bahasa

Платформа для изучения индонезийского языка (Bahasa Indonesia).

## Стек

- **Next.js 15** (App Router, RSC)
- **TypeScript**
- **Tailwind CSS** + CSS-переменные (тема под shadcn/ui)
- **shadcn/ui** (заготовка `components.json`, алиасы `@/components`, `@/lib`)
- **lucide-react** для иконок

Проект подготовлен под добавление компонентов из [v0.app](https://v0.app) — копируйте компоненты прямо в `components/ui/`.

## Локальный запуск

```bash
npm install
npm run dev
```

Сайт откроется на http://localhost:3000.

## Озвучка словаря

Индонезийские слова озвучены голосами ElevenLabs через [Voicer API](https://voicer.mat3u.com/docs).
Готовые MP3 лежат в `public/audio/id/` и отдаются как статика — внешних
запросов в рантайме нет, и в оффлайне они работают из кеша service worker'а.

Имя файла — это `FNV-1a`-хэш от `id:<текст>`. Хэш считается одинаково в
[`lib/audio-url.ts`](lib/audio-url.ts) и в скрипте генерации, поэтому фронт
находит файл без индекса. Нет файла — [`SpeakButton`](components/speak-button.tsx)
и [`FlashcardPlayer`](components/flashcard-player.tsx) молча падают на
системный голос Web Speech, как было раньше.

Для генерации нужен ключ в `.env.local`:

```
VOICER_API_KEY=...
```

```bash
npm run audio:voices   # голоса-кандидаты
npm run audio:sample   # начитать демо каждым голосом в public/audio/_samples
npm run audio:dry      # сколько символов уйдёт и сколько осталось квоты
npm run audio:gen      # озвучить слова
```

Скрипт идемпотентен: уже озвученное на диске пропускается, так что после
обрыва достаточно перезапустить. Примеры к словам по умолчанию не озвучиваются
(это ещё ~106 тысяч символов против ~10 тысяч на слова) — включаются флагом:

```bash
npm run audio:gen -- --examples
npm run audio:gen -- --voice=george   # другой голос
```

Как это работает под капотом: у Voicer асинхронное API (задача → опрос →
скачивание), а `split_type: "paragraphs"` + `split_output: true` возвращают
ZIP из отдельных MP3 — по одному на абзац. Скрипт склеивает батч фраз через
пустую строку и раскладывает чанки архива по именам, поэтому 1262 слова
стоят 13 задач, а не 1262 запроса. Если число чанков не совпало с числом
фраз, батч отбрасывается целиком: лучше недостача, чем озвучка под чужим именем.

## Читалка

Вкладка **Чтение** (`/reading`) — книги с тремя подсказками поверх текста.
Сейчас их три: два детектива на разговорном индонезийском и
`ai-business-english` — ридер по деловому английскому (12 глав про AI,
процессы, стартапы, деньги и команды, уровень B1–B2). Подсказки одни и те же:

- **наведение (или тап) на слово** — перевод во всплывашке, с базовой формой,
  если словоформа отличается от словарной (`rumahnya` → «его дом», от `rumah`);
- **кнопка ⇄ у предложения** — перевод предложения целиком прямо в строке,
  плюс тумблер «перевод везде» в шапке главы;
- **значок 🔊 в конце предложения** — озвучка. Значки стоят в потоке текста
  и видны всегда: плавающая панель для этого не годилась — гасла, стоило
  увести курсор, и прицелиться в неё было нельзя. Озвучка выключается
  тумблером «Озвучка» в шапке главы.

**Свои наборы слов.** Звёздочка во всплывашке над словом кладёт его в
«Избранное», а из него слова раскладываются по своим наборам
(`/vocab/my/<id>`) и учатся теми же карточками, что и готовые наборы из
`data/vocab`. Хранилище — localStorage (`lib/use-word-sets.ts`), как у
прогресса и выученных слов: наборы принадлежат устройству и не требуют
аккаунта.

Названия книги и глав тоже переводятся: перевод стоит под оригиналом на
витрине, в оглавлении и над текстом главы. Ключ тот же — сам текст заголовка.

**Язык книги** лежит в поле `lang` её `.json` — его проставляет
`scripts/build-reading.mjs` по карте `LANGS` в своей шапке (умолчание — `id`,
исключения перечислены поимённо). От языка зависит всё остальное: папка
озвучки `public/audio/<lang>/`, голос Web Speech, когда MP3 нет, и то, каким
промптом переводит `translate-reading.mjs`.

Всё это офлайн: ни перевод, ни озвучка не ходят в сеть в рантайме. Кнопки
предложения плавают отдельным слоем, а не стоят в потоке текста, — иначе они
раздвигали бы строки на свою ширину даже невидимыми.

### Как добавить книгу

1. Положи `data/reading/<slug>.md` — обычный markdown: `# Заголовок`,
   `### подзаголовок` (до первой главы — подзаголовок книги, внутри главы —
   её подзаголовок), `## N. Название главы`, абзацы, цитаты `>`, `*курсив*`.
   Второй заголовок первого уровня (`# DAFTAR KATA`, `# BAGIAN BELAKANG` —
   название неважно) считается началом приложения: всё после него уходит
   отдельной страницей `/reading/<slug>/appendix` и рендерится как есть.
   Цитата, начинающаяся с одиночного `**Заголовка**`, а дальше содержащая
   список пар `слово — перевод · слово — перевод`, становится врезкой-словариком
   (как «Kata Baru» в `perahu-terakhir`, как «Useful Phrases» в
   `ai-business-english`): без кнопок перевода и озвучки, потому что это уже
   перевод. Таблица `| … | … |` со строкой-разделителем под шапкой рисуется
   таблицей (`Key Vocabulary`) — тоже без кнопок и мимо глоссария.
   Если книга не на индонезийском, впиши её slug в карту `LANGS` в шапке
   `scripts/build-reading.mjs`, иначе она уедет в озвучку как индонезийская.
2. Обложка — `public/reading/<slug>.svg` (или `.png`/`.jpg`/`.webp`),
   пропорции 2:3. Нет файла — карточка нарисует заглушку.
3. Собери и переведи:

```bash
npm run reading:build -- <slug>       # .md → <slug>.json: главы, предложения, токены
npm run reading:translate -- <slug>   # переводы предложений и словарь всех словоформ
npm run reading:check -- <slug>       # у всех ли предложений есть перевод
npm run audio:reading=<slug>          # MP3 на каждое предложение
```

### Второй маршрут: книга из двуязычного исходника

Когда перевод пишется руками, а не скриптом, книгу удобнее держать сразу на
двух языках: `data/reading/duo/<slug>.duo.md`, где на каждой строке
`Kalimat asli. | Перевод.`. [`scripts/build-duo.mjs`](scripts/build-duo.mjs)
разворачивает такой файл в обычный `<slug>.md` и в `<slug>.translations.json`.

Так сделаны пять детективов: `surat-dari-bogor`, `hujan-di-stasiun-tugu`,
`pintu-yang-terkunci`, `lonceng-di-kampus`, `pukul-tujuh-lewat-lima`.

Смысл формата — в ключах. Ключ перевода это точный текст предложения после
разбора `build-reading.mjs`; разойдись он на один символ, абзац молча
останется без кнопки ⇄. Здесь оригинал и перевод стоят на одной строке и
ключи генерируются из того же источника, так что разойтись им негде. Скрипт
заодно ругается на строки, которые склеятся при разборе (предложение со
строчной буквы) или не кончаются знаком препинания.

```bash
npm run reading:duo -- <slug>         # duo/<slug>.duo.md → <slug>.md + translations.json
npm run reading:build -- <slug>
npm run reading:glossary -- <slug>    # глоссарий из соседних книг и врезок «Kata Baru»
npm run reading:check -- <slug>
```

[`scripts/seed-glossary.mjs`](scripts/seed-glossary.mjs) не переводит слова, а
берёт готовые: словоформы у книг на одном языке общие, и новая книга получает
перевод по наведению из уже переведённых. Что не нашлось нигде — имена,
топонимы, редкие формы — лежит в общем `data/reading/<lang>-extra.glossary.json`,
он идёт первым в пуле. Непокрытый остаток скрипт выписывает в
`<slug>.glossary-todo.json`.

Без `<slug>` скрипты берут `kabut-di-lembang`. Голос озвучки привязан к книге
в `READING_VOICES` (`scripts/generate-audio-voicer.mjs`) — у каждой книги свой
рассказчик; нет книги в списке — берётся общий голос её языка, а флаг
`--voice=<id>` переопределяет и то, и другое.

Переводит [`scripts/translate-reading.mjs`](scripts/translate-reading.mjs) —
через `claude -p`, то есть по подписке Claude Code, без всякого API-ключа.
Промпт выбирается по `book.lang`: индонезийскому роману нужен живой
разговорный русский и частицы, английскому бизнес-ридеру — деловой регистр и
термины, которые по-русски не переводят (`churn`, `runway`, `product-market
fit`). Если приложение книги содержит двухколоночную таблицу
(`| English | Русский |`), она целиком уезжает в промпт справочником терминов —
иначе `churn` в одной главе станет «оттоком», а в другой «текучестью».
Предложения, уже написанные по-русски (вступление английской книги наполовину
русское), не переводятся вовсе: у такого абзаца читалка просто не рисует
кнопку ⇄.
Ключ перевода — сам текст предложения, а не его номер, поэтому скрипт
идемпотентен: его можно прерывать, запускать снова (доберёт только
недостающее) и перепарсивать книгу, не обесценивая уже сделанное.

```bash
npm run reading:translate -- --only=words --jobs=6
npm run reading:translate -- --limit=20 --batch=10   # проба на кусочке
```

Результат — три файла рядом с книгой: `<slug>.json` (разобранный текст),
`<slug>.translations.json` (`предложение → перевод`) и `<slug>.glossary.json`
(`словоформа → { ru, lemma }`). В браузер уезжает только открытая глава с её
переводами и тем куском глоссария, который в ней реально встречается —
см. `chapterTranslations`/`chapterGlossary` в [`lib/reading.ts`](lib/reading.ts).

Озвучка книги — тот же скрипт, что и для словаря, с флагом `--reading`:
имена MP3 считаются тем же хэшем, поэтому фраза, уже озвученная для словаря,
второй раз не тратит квоту.

## Экспресс — частицы и аффиксы

Отдельная вкладка `/express`: модуль из 32 юнитов с интерактивным тренажёром.
Содержание — из `EXPRESS-MODULE-1.md`, два блока с наибольшей отдачей:
частицы (`ya`, `kan`, `sih`, `dong`, `kok`, …) и аффиксы (`meN-`, `ber-`,
`di-`, `ter-`, `-kan`, `-i`, `-in`, `-an`, `peN-`, `ke-…-an`).

| Экран | Что там |
|---|---|
| `/express` | обзор: две дорожки по неделям, прогресс, скорость механики `meN-` |
| `/express/<юнит>` | теория, материал с озвучкой, тренажёр, чеклист |
| `/express/repeat` | работа над ошибками: задания со всего модуля, где ошибок больше, чем верных ответов |
| `/express/reference` | справочник одной страницей: карта частиц, мост из русского, KTSP, регистр, 24 корня |

### Данные

```
data/express/particles.json   12 частиц: функции, примеры со сценами, мост, связки, минимальные пары
data/express/roots.json       24 корня со всеми формами, механика meN-, книжное ↔ разговорное
data/express/units/*.json     юнит целиком: теория, чеклист и его дриллы
```

Один файл — один юнит; дриллы лежат внутри него, а не отдельной колодой.
Загрузчик — [`lib/express.ts`](lib/express.ts), серверный (читает диск).
Клиентские компоненты берут типы из
[`lib/express-types.ts`](lib/express-types.ts) — иначе сборка падает на
`UnhandledSchemeError`, ровно как у читалки.

### Тренажёр

Девять типов заданий из спецификации. Экран определяется полем `mode`:
`choice` (варианты), `input` (ввод), `fields` (несколько полей),
`selfcheck` (сказал вслух — сверься с образцом).

- варианты **перемешиваются** детерминированно от `id` дрилла и номера захода:
  в данных правильный ответ часто стоит первым, и без перемешивания выбор
  быстро идёт по позиции, а не по смыслу;
- ошибка возвращает задание в конец очереди, но **в счёт идёт первый ответ** —
  повтор закрепляет, а не «дорисовывает» балл;
- `men_drill` идёт с таймером: истёк — промах. Механика тренируется только на
  скорость, медленный правильный ответ здесь не считается;
- ответ сверяется мягко: регистр, лишние пробелы, точка в конце и запись
  аффикса через дефис вместо плюса ошибкой не считаются
  (`normalizeAnswer` в `lib/express-types.ts`);
- прогресс — в localStorage устройства (`belajar:express:v1`), как свои наборы
  карточек. В Supabase не уходит: `lesson_progress` хранит числовой `lesson_id`,
  а тут строковые юниты.

### Озвучка модуля

```bash
npm run audio:dry                 # остаток квоты
npm run audio:express             # озвучить всё индонезийское из data/express
```

Флаг `--express` собирает индонезийские строки модуля: примеры частиц, формы
и примеры корней, материал дриллов. Русские формулировки и служебные записи
аффиксов (`peN- + -an`, `ter-`) отфильтровываются — озвучивать там нечего.
Имена файлов считаются тем же хэшем, что и у словаря, поэтому уже озвученная
фраза второй раз квоту не тратит.
