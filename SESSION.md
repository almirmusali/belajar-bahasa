## Как всё устроено

**Имена файлов.** `public/audio/<lang>/<fnv1a(lang:текст)>.mp3`. Хэш FNV-1a
считается одинаково в `lib/audio-url.ts` и в скрипте генерации, поэтому
фронтенду не нужен индекс. Нет файла — 404, и плеер молча уходит на системный
Web Speech.

**Генерация** — `scripts/generate-audio-voicer.mjs`. У Voicer асинхронное API
(задача → опрос → скачивание ZIP). Ключевой приём: `split_type: "paragraphs"` +
`split_output: true` возвращают ZIP из отдельных MP3, по одному на абзац.
Поэтому батч фраз склеивается через пустую строку и уходит одной задачей:
1262 слова — это 13 задач, а не 1262 запроса. Если число чанков в ответе не
совпало с числом фраз, батч отбрасывается целиком — лучше недостача, чем MP3
под чужим именем.

```bash
npm run audio:voices   # какие голоса на какие языки настроены
npm run audio:sample   # демо-нарезка в public/audio/_samples (папка в .gitignore)
npm run audio:dry      # объём и остаток квоты, ничего не тратит
npm run audio:gen      # озвучить
```

Флаги: `--lang=id,ru,en`, `--voice=<id>` (только с одним `--lang`), `--force`
(перезапись — нужна при смене голоса, т.к. имя файла зависит от текста, а не от
голоса), `--examples`, `--set=<папка>`, `--batch=N`, `--limit=N`, `--dry`.

Нужен `VOICER_API_KEY` в `.env.local`. **Ключ в git не уходит** (`.env*` в
`.gitignore`) — на новой машине его надо положить заново.

## Развёртывание

Важно: **сервис работает на этом же Mac Studio**, никакого ssh не нужно.
launchd-агент `com.almir.belajar-bahasa` поднимает `next start -H 0.0.0.0 8766`
из `~/belajar-bahasa`, а разработка идёт в `~/Code/belajar-bahasa`. Это две
разные папки — если забыть про это, правки «не доезжают» до телефона.

```bash
./deploy.sh          # бэкап → синхронизация → сборка → перезапуск
./deploy.sh --logs   # логи сервиса
```

Скрипт исключает `node_modules`, `.env*` (у живой копии может быть своя
конфигурация), `.next`, сэмплы и временные архивы. Бэкапы исходников кладутся
рядом: `~/belajar-bahasa.backup-<дата>`.

Доступ с телефона: **http://mac-studio:8766** через Tailscale.

## Изменения в интерфейсе

- `lib/audio-url.ts` — включён, отдаёт URL для всех трёх языков.
- `lib/speak-id.ts` — общая озвучка одной фразы (MP3 → фолбэк Web Speech).
  Используется `SpeakButton` и списком выученных. Есть защёлка: 404 роняет и
  `onerror`, и `play().catch()`, без неё фраза произносилась дважды.
- `lib/audio-element.ts` — один переиспользуемый `<audio>` на всё приложение.
  Нужен для фоновой озвучки: iOS выдаёт разрешение играть конкретному элементу
  после касания, и только он продолжает звучать в фоне. Новый элемент,
  созданный уже в фоне, играть не начнёт. Плюс MediaSession — метаданные и
  кнопки на экране блокировки.
- `components/flashcard-player.tsx`:
  - по умолчанию озвучиваются все три языка, так что на стороне перевода звучат
    и английский, и русский (раньше русский был выключен);
  - на скорости 1.5 с сторона перевода живёт 2.5 с — двух языков в 1.5 с не
    вмещалось;
  - примеры под карточкой кликабельны (`ExampleLine`). Это не `<button>`:
    карточка сама кнопка, вложенная кнопка — невалидный HTML и ошибка гидрации.
    Нужен `stopPropagation`, иначе клик переворачивает карточку;
  - в фоне сторону переключает не таймер, а сама озвучка: iOS придушивает
    `setTimeout`, поэтому после цепочки играется секунда тишины
    (`public/audio/silence-1s.mp3`) и карточка идёт дальше.
- `public/sw.js` — `VERSION` поднят до `v6`; RSC-пейлоады (`?_rsc=`) больше не
  кешируются. Именно это давало «Application error: a client-side exception» на
  телефоне: они попадали в ветку cache-first без срока жизни, хотя привязаны к
  `buildId`, и старый RSC склеивался со свежими чанками.
- `components/sw-register.tsx` — регистрация висела на `window.addEventListener("load")`
  внутри `useEffect`; к моменту гидрации `load` уже прошёл, обработчик не
  вызывался, и SW никогда не обновлялся. Добавлена проверка `document.readyState`.

## Что осталось открытым

1. **Проверить телефон.** Ошибка на телефоне была из-за залипшего SW v5.
   Нужно открыть http://mac-studio:8766 и перезагрузить; если не помогло —
   удалить установленную иконку PWA и открыть заново. Проверить не удалось:
   доступа к консоли телефона нет.
2. **Фоновая озвучка не проверена на реальном iOS.** Локально подтверждено:
   элемент один, метаданные MediaSession заполняются, цепочка играет
   переключением `src` у одного элемента. Как это ведёт себя при реальном
   уходе в другое приложение — надо слушать на телефоне.
3. **Примеры озвучены только в наборе `greetings`** — как образец. На все
   33 набора: `npm run audio:gen -- --examples --lang=id,ru`, это ~212 000
   символов (в остаток квоты укладывается) и несколько часов.
4. **Порядок озвучки перевода** — сейчас английский, затем русский, следом за
   визуальным порядком на карточке. Если удобнее русский первым — поменять в
   эффекте цепочки в `flashcard-player.tsx`.
5. **Устаревшие скрипты** `scripts/generate-audio.mjs` и
   `generate-audio-azure.mjs` льют в Supabase Storage, откуда теперь ничего не
   читается. Не удалял — решение за владельцем.
6. **Размер репозитория.** 74 MB аудио теперь в git. Для домашнего сервера это
   нормально; если понадобится Vercel — стоит подумать про внешнее хранилище.

## Мелочи, о которые легко споткнуться

- `gh` не авторизован, HTTPS-push просит пароль. Push идёт по SSH — remote
  переключён на `git@github.com:almirmusali/belajar-bahasa.git`.
- `ssh mac-studio` отвечает `Permission denied (publickey)` — машина стучится
  сама к себе, своего ключа в `authorized_keys` нет. Не нужно: деплой локальный.
- В живой копии `~/belajar-bahasa` нет `.env.local`, поэтому Supabase там не
  настроен и приложение работает в анонимном режиме (только localStorage).
