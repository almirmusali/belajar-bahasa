Документ для продолжения работы на другой машине или в новом диалоге.
Ниже — состояние на 24 августа 2026 и всё, что нужно знать, чтобы не
наступить на уже найденные грабли.

## Состояние

Всё закоммичено и разложено по трём местам:

| где | адрес | ветка |
|-----|-------|-------|
| GitHub | `almirmusali/belajar-bahasa` | `main` = `audio-voiceover` |
| Vercel (продакшн) | https://belajar-bahasa.vercel.app | автодеплой с `main` |

```bash
git clone https://github.com/almirmusali/belajar-bahasa.git
cd belajar-bahasa && npm install && npm run dev
```

`audio-voiceover` влита в `main` без расхождений, обе ветки указывают на один
коммит. Дальше можно работать прямо в `main`.

**Репозиторий публичный.** Вместе с кодом там лежат обе книги и ~250 МБ
озвучки. Секретов в нём нет (`.env*` в `.gitignore`), но иметь в виду стоит.

## Что нужно положить руками

**`.env.local`** — в git не уходит и на новой машине его не будет:

```
VOICER_API_KEY=<ключ от voicer.mat3u.com>
NEXT_PUBLIC_SUPABASE_URL=...      # необязательно
NEXT_PUBLIC_SUPABASE_ANON_KEY=... # необязательно
```

Без Supabase приложение работает в анонимном режиме на localStorage — весь
курс, словарь и читалка доступны. Ключ Voicer нужен только для генерации
новых MP3; в рантайме приложение его не читает.

**Свои наборы слов не переедут.** «Избранное» и пользовательские наборы
живут в localStorage конкретного браузера (`belajar:wordsets:v1`). На другой
машине они будут пустые — это осознанный выбор, наборы принадлежат
устройству и не требуют аккаунта.

## Читалка: как устроена

Вкладка `/reading`, три книги:

| книга | язык | голос озвучки | объём |
|-------|------|---------------|-------|
| «KABUT DI LEMBANG» | `id` | `21m00Tcm4TlvDq8ikWAM` | 25 глав, 13 716 слов, 2324 предложения |
| «PERAHU TERAKHIR» | `id` | `52LXmmR0nGnIcDs1TL3f` | 23 главы, 8 376 слов, 1660 предложений |
| «AI & Business English» | `en` | голос языка, `uYXf8XasLslADfZ2MB4u` | 13 глав, 8 472 слова, 613 предложений |

Первые две переведены и озвучены полностью. Третья переведена полностью
(614 предложений, 1956 словоформ), **но не озвучена**: MP3 стоят 51 737
символов квоты Voicer, и решение — за владельцем ключа. Пока их нет, кнопка
🔊 читает системным английским голосом, а на витрине у книги стоит честная
метка «голос браузера» вместо «озвучка» (`hasStudioAudio` в `lib/reading.ts`).
Озвучить, когда понадобится:

```bash
npm run audio:reading -- --reading=ai-business-english
```

Взаимодействия — перевод слова по наведению, перевод и озвучка абзаца,
звёздочка «в избранное». Всё офлайн: ни перевод, ни озвучка не ходят в сеть
в рантайме.

**Язык книги** живёт в поле `lang` её `.json` — карта `LANGS` в шапке
`scripts/build-reading.mjs`. От него зависят папка `public/audio/<lang>/`,
голос Web Speech и то, каким промптом переводит `translate-reading.mjs`.
Отдельные абзацы могут быть на своём языке: вступление английского ридера
наполовину написано по-русски, такие абзацы помечены `lang: "ru"` — их не
переводят и читают русским голосом, а не английским.

Подробности формата и команды — в [README](README.md#читалка). Коротко:

```bash
npm run reading:build -- <slug>       # data/reading/<slug>.md → <slug>.json
npm run reading:translate -- <slug>   # переводы и словарь — через claude -p
npm run audio:reading=<slug>          # MP3 на каждое предложение
```

**Переводит `claude -p`** — то есть Claude Code по подписке, без API-ключа.
Ключ перевода — сам текст предложения, поэтому скрипты идемпотентны: можно
прерывать, дозапускать и перепарсивать книгу, не теряя работу.

**В `.gitignore` есть общее правило `*.mp3`** (от автопрогона «подготовки к
публикации»). Ниже стоят исключения `!public/audio/**` и `!public/reading/**`,

новая озвучка молча перестанет попадать в коммиты, а поломка будет тихой —
уже закоммиченное правило не трогает.

**Врезка «Kata Baru» опознаётся по одиночному `**заголовку**`** в начале
цитаты. Шаблон обязан запрещать звёздочки внутри: иначе под него попадают
строки хронологии вроде `**22:50** — Bambang lewat lorong. **Meja kosong.**`
и абзац исчезает целиком. Блок считается словариком только начиная с трёх пар.

**`lib/reading.ts` читает диск через `node:fs`.** Клиентские компоненты
должны импортировать типы из `lib/reading-types.ts`, иначе сборка падает на
`UnhandledSchemeError`.

**Деплой запускается на самой Mac Studio**, а не с ноутбука: `deploy.sh`
синхронизирует `~/Code/belajar-bahasa` → `~/belajar-bahasa` внутри одной
машины. С ноутбука это делается так:

```bash
ssh mac-studio 'export PATH=/opt/homebrew/bin:$PATH; cd ~/Code/belajar-bahasa && git pull --ff-only && ./deploy.sh'
```

Сервису нужно около 30 секунд на прогрев после перезапуска — проверка сразу
после `kickstart` вернёт «нет ответа», это не ошибка.

**Пуш большого объёма по HTTPS падает** с `RPC failed; HTTP 400`. Лечится
один раз на репозиторий:

```bash
git config http.postBuffer 1048576000
git config http.version HTTP/1.1
```

## Как всё устроено

**Имена файлов.** `public/audio/<lang>/<fnv1a(lang:текст)>.mp3`. Хэш FNV-1a
считается одинаково в `lib/audio-url.ts` и в скрипте генерации, поэтому
фронтенду не нужен индекс. Нет файла — 404, и плеер молча уходит на системный
Web Speech.

**Генерация** — `scripts/generate-audio-voicer.mjs`. У Voicer асинхронное API
(задача → опрос → скачивание ZIP). Ключевой приём: `split_type: "paragraphs"` +
`split_output: true` возвращают ZIP из отдельных MP3, по одному на абзац.
Поэтому батч фраз склеивается через пустую строку и уходит одной задачей:
1262 слова — это 13 задач, а не 1262 запроса. Если число чанков в ответе не
совпало с числом фраз, батч отбрасывается целиком — лучше недостача, чем MP3
под чужим именем.

```bash
npm run audio:voices   # какие голоса на какие языки настроены
npm run audio:sample   # демо-нарезка в public/audio/_samples (папка в .gitignore)
npm run audio:dry      # объём и остаток квоты, ничего не тратит
npm run audio:gen      # озвучить
```

Флаги: `--lang=id,ru,en`, `--voice=<id>` (только с одним `--lang`), `--force`
(перезапись — нужна при смене голоса, т.к. имя файла зависит от текста, а не от
голоса), `--examples`, `--set=<папка>`, `--batch=N`, `--limit=N`, `--dry`.

Нужен `VOICER_API_KEY` в `.env.local`. **Ключ в git не уходит** (`.env*` в
`.gitignore`) — на новой машине его надо положить заново.

## Развёртывание

Важно: **сервис работает на этом же Mac Studio**, никакого ssh не нужно.
launchd-агент `com.almir.belajar-bahasa` поднимает `next start -H 0.0.0.0 8766`
из `~/belajar-bahasa`, а разработка идёт в `~/Code/belajar-bahasa`. Это две
разные папки — если забыть про это, правки «не доезжают» до телефона.

```bash
./deploy.sh          # бэкап → синхронизация → сборка → перезапуск
./deploy.sh --logs   # логи сервиса
```

Скрипт исключает `node_modules`, `.env*` (у живой копии может быть своя
конфигурация), `.next`, сэмплы и временные архивы. Бэкапы исходников кладутся
рядом: `~/belajar-bahasa.backup-<дата>`.

Доступ с телефона: **http://mac-studio:8766** через Tailscale.

## Изменения в интерфейсе

- `lib/audio-url.ts` — включён, отдаёт URL для всех трёх языков.
- `lib/speak-id.ts` — общая озвучка одной фразы (MP3 → фолбэк Web Speech).
  Используется `SpeakButton` и списком выученных. Есть защёлка: 404 роняет и
  `onerror`, и `play().catch()`, без неё фраза произносилась дважды.
- `lib/audio-element.ts` — один переиспользуемый `<audio>` на всё приложение.
  Нужен для фоновой озвучки: iOS выдаёт разрешение играть конкретному элементу
  после касания, и только он продолжает звучать в фоне. Новый элемент,
  созданный уже в фоне, играть не начнёт. Плюс MediaSession — метаданные и
  кнопки на экране блокировки.
- `components/flashcard-player.tsx`:
  - по умолчанию озвучиваются все три языка, так что на стороне перевода звучат
    и английский, и русский (раньше русский был выключен);
  - на скорости 1.5 с сторона перевода живёт 2.5 с — двух языков в 1.5 с не
    вмещалось;
  - примеры под карточкой кликабельны (`ExampleLine`). Это не `<button>`:
    карточка сама кнопка, вложенная кнопка — невалидный HTML и ошибка гидрации.
    Нужен `stopPropagation`, иначе клик переворачивает карточку;
  - в фоне сторону переключает не таймер, а сама озвучка: iOS придушивает
    `setTimeout`, поэтому после цепочки играется секунда тишины
    (`public/audio/silence-1s.mp3`) и карточка идёт дальше.
- `public/sw.js` — `VERSION` поднят до `v6`; RSC-пейлоады (`?_rsc=`) больше не
  кешируются. Именно это давало «Application error: a client-side exception» на
  телефоне: они попадали в ветку cache-first без срока жизни, хотя привязаны к
  `buildId`, и старый RSC склеивался со свежими чанками.
- `components/sw-register.tsx` — регистрация висела на `window.addEventListener("load")`
  внутри `useEffect`; к моменту гидрации `load` уже прошёл, обработчик не
  вызывался, и SW никогда не обновлялся. Добавлена проверка `document.readyState`.

## Сессия 6 августа, вторая половина: фон и машина

**Озвучка вставала после первой карточки в фоне.** Автопрокрутка была завязана
на ререндер React: цепочка доигрывала, дёргала `advance()`, и дальше ждала, пока
пересчитается эффект. В фоне iOS придушивает планировщик — этого не случалось.
Хуже того, при скрытой странице таймер отключён, а цепочку никто не начинал:
нажали «Авто» (или экран погас) между карточками — не звучало вообще ничего.

Теперь пока страница скрыта, очередь ведёт `runHiddenLoop` в
`flashcard-player.tsx`: следующий `src` ставится прямо по событию `ended`, без
ожидания эффектов, всё нужное читается из ref'ов (`cfgRef`, `stateRef`).
Состояние React обновляется следом — только чтобы нарисовать карточку и
метаданные экрана блокировки. Возврат на экран гасит петлю, дальше снова таймер.
Проверено на живой сборке: сотня событий озвучки подряд при `document.hidden`.

**В машине часть фраз молчала целиком.** `<audio>` уходил за MP3 ровно в момент
фразы; по сотовой сети через Tailscale запрос иногда не успевал — и фраза
пропадала. Теперь файл сначала скачивается (`lib/audio-cache.ts`), а элементу
отдаётся `blob:` — данные уже в памяти, сеть в момент воспроизведения не
участвует. Текущая карточка и три следующие греются заранее, сорвавшаяся
загрузка повторяется один раз. В настройках озвучки есть кнопка «Скачать
озвучку набора» — набор закрепляется в памяти целиком.

**Адрес сменился на https.** `http://mac-studio:8766` — не защищённый контекст,
и браузер не даёт там ни service worker, ни Cache API: оффлайн-кеша на этом
адресе нет вовсе. Включены HTTPS Certificates в админке Tailscale и поднят
прокси:

    tailscale serve --bg --https=443 http://127.0.0.1:8766

Рабочий адрес теперь **https://mac-studio.tail667b0c.ts.net** — там secure
context, service worker регистрируется, кеш переживает перезагрузку (проверено:
91 файл набора `animals` остаётся в кеше после reload). Прямой http на 8766
никуда не делся и продолжает работать, но без оффлайна. Иконку PWA на телефоне
надо переустановить с https-адреса.

Выключить прокси, если понадобится: `tailscale serve --https=443 off`.

## Мелочи, о которые легко споткнуться

- `gh` не авторизован, HTTPS-push просит пароль. Push идёт по SSH — remote
  переключён на `git@github.com:almirmusali/belajar-bahasa.git`.
- `ssh mac-studio` отвечает `Permission denied (publickey)` — машина стучится
  сама к себе, своего ключа в `authorized_keys` нет. Не нужно: деплой локальный.
- В живой копии `~/belajar-bahasa` нет `.env.local`, поэтому Supabase там не
  настроен и приложение работает в анонимном режиме (только localStorage).
